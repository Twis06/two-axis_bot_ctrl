### Governor structure

Each step emits exactly one of the following:

- **PATH**: the admitted path on its own clock σ.
- **JOIN**: a minimum-jerk segment between stationary holdable points. JOIN also includes a small start-offset blend that runs with the clock moving.
- **STOP**: constant deceleration to rest. It is re-planned every step. It stays within the budget unless that would leave the holdable interval, in which case it uses the reserve.
- **HOLD**: stationary at a restricted point until both the path point and the path 10 ms ahead are holdable again.

In every mode:

- Velocity is either the analytic segment or trapezoidal integration, and acceleration is the step average, so the emitted (q, v, a) are consistent by construction.
- The clock is frozen outside PATH.

There is no follower, no root finding, and no reference motion used to cancel a disturbance.

Every step also reports:

- **status**: `accepted | reshaped | joining | restricted | over_budget | rejected`, with a reason string;
- **infeasibility**: `static` (a position cannot be held), `dynamic` (a path cannot be traversed within budget at any speed), `braking` (a limit drop took the braking room), or empty.

Invalid input is rejected and latched. This covers non-finite samples, limits, loads and coupling, and any plan that produces three or more discontinuities within 0.05 s of path time.

## 2. Reproduced failures (before)

| Case | Result at `checkpoint-pre-2A` |
|---|---|
| Hold(0) under 0.4 N·m coupling, standalone | The reference drifts to −0.64 rad; never flagged. |
| Hold(0) under 0.8 N·m coupling, standalone | The reference runs away to −37.4 rad at −20 rad/s; never flagged. |
| Same through the host | The reference drifts 5.4 rad. |

Independent review of the first 2A implementation: **FAIL**. It raised eight major findings, M1–M8:

- **M1:** path jumps passed straight through.
- **M2:** fast paths stalled while labelled "reshaped".
- **M3:** every start or realignment lost at least 0.3 s of path clock; run A wall-clock RMS went 0.73° → 32°.
- **M4:** the braking-room stop was a velocity step and was not surfaced.
- **M5:** active joins were never re-checked after a derate.
- **M6:** the inward-step loop moved the reference away from the request.
- **M7:** a NaN plan sample became a 90° full-current move.
- **M8:** over-budget escalation handed control to passive fallback, which ran away.

Second review: **FAIL**, with three further defects:

- **N1:** the STOP deceleration was never re-planned, so the reference coasted to −133° or exceeded capacity silently.
- **N2:** a restricted hold never resumed after the limit was restored.
- **N3:** a velocity kink near ±90° drove the reference past the travel limit.

The executor's own matched-seed evaluations found:

- clock loss at start-up sync (0.30 s);
- a re-join after an outage that ignored coupling, winding the integrator (the axis held 5° off for 0.4 s);
- yaw shrunk to zero with no coupling present;
- saturation back-off (`kappa`) forgotten at each re-arm (33 watchdog trips);
- encoder-offset start joins (+6.5° wall-clock RMS in run A).

The fuzz harness from the second review exposed inconsistent-plan loops and a stuck hold.

Third review: **PASS WITH ISSUES**. It required two fixes before Packet 2B:

- a first-step torque spike after every resync onto a moving path (1.4–1.8× the budget; through the host it permanently halved yaw after an outage);
- velocity kinks crossed at s ≈ 0.24 (an acceleration step of 11× capacity, and up to 0.6° of overshoot).

It also found that STOP steps above capacity were not labelled `over_budget`.

The reviewer's delta check confirmed all three fixed: 0.90× budget on the first step, kinks at ≤ 0.78× capacity with no overshoot, and the labelling corrected. It found one narrow new regression: a single legitimate jump was rejected as an "inconsistent plan" while the saturation back-off was at its floor. That was fixed and sent for a second delta check (§6).

Each item has a regression test in `tests/test_governor_contract.py`.

## 5. Remaining limitations

- **Declared regression: loaded outage recovery cycles through trip and re-arm much more often.**
  - Payload E with a 100 ms feedback-only loss, seeds 1–10: watchdog trips went from a median of 4 (range 0–5, fallback about 3 %) to a median of 33 (range 0–37, fallback up to 18.6 %). The governed peak is lower (10.3–18.8° against 12.6–21.8°).
  - The Monte Carlo D/E trip totals rise (79 → 117, 127 → 139) by the same mechanism; the same trials trip as before.
  - Mechanism: after a watchdog re-arm the governor resumes the same request at its nominal-budget speed. The unmodelled payload makes it unfollowable again, so the axis trips again. The old follower's own acceleration limit happened to damp this.
  - The case is multimodal across seeds (0, about 10, or about 35 trips), so single-seed rows are not a reliable before/after measure.
  - This is not tuned away inside 2A. It is the first item for Packet 2B, recovery by fault class: "a persistent tracking/load fault must not be cleared solely by moving the reference" (EXECUTION_PLAN.md). The request should not resume automatically after a tracking fault without a replan or evidence of feasibility.
- **More time at the current limit under the unmodelled payload** (D/E at-limit p95 up 7–9 points). The governor judges feasibility with the nominal model. Payload estimation is the Task 3 question.
- **No yaw authority (deferred to 2B).**
  - The pre-existing YawMonitor path still rejects to passive fallback when there is no planner. It is pinned by `test_hardening.py::test_uncoordinated_yaw_saturation_rejects_request`. The skipped test M8c records the reviewer's reproducer: 0.4 N·m leads to about an 800° runaway.
  - Coupling beyond actuator capacity (0.8 N·m) runs away even with a planner, because the 0.5 s yaw blend is slower than the 40 ms watchdog. This is physically unavoidable at the roll axis.
- **Declared tolerances:**
  - position snap of up to 1.5 encoder counts on the first sync after a host reset;
  - a stop may end up to about one count past a boundary, then return to it;
  - trapezoid error of about 5e-6 rad on 90° moves of 25 samples or fewer.
- **Reference demand above the budget:**
  - Under adversarial limit switching, a reshaped step's demand, computed without coupling, can exceed capacity by up to 0.075 N·m (fuzz). With coupling included it stays within the labelled status.
  - Braking and return segments may use the reserve (above the budget, within capacity) and are labelled `restricted`; steps above capacity are labelled `over_budget`.
- **Plans must supply consistent (q, v, a):**
  - A zero-order-hold setpoint staircase at ≥ 50 Hz is rejected as an inconsistent plan; one at 10–20 Hz crawls. Such streams need an interpolating front end.
  - Fast limit toggling (every 6–100 ms) makes the reference move between boundaries with the clock nearly frozen. It is labelled restricted and never hangs.
  - Discontinuity detection is tuned for the host's 2 ms step; at ts ≥ 20 ms it can flag smooth paths.
- **Kinks slow the clock more:** for example, path lag on an 80° / 3 rad/s triangle grew from 0.80 to 1.64 s.
- **Consistent braking overshoots more** than the old velocity-step stop in one closed-loop case: 42.9° against 36.2°. The old stop was inconsistent and effectively commanded saturation. The consistent brake was kept deliberately.
- **Behaviour change:** a stationary reference outside the reserved interval but within actuator capacity now returns to the boundary using the reserve (restricted), instead of being rejected into passive fallback. The first-round 2A test was split into within-capacity and beyond-capacity cases.
- `incompatible` stays set until the host calls `replan()`. No planner-side replan exists yet (2B information mode).

## 6. Gate result

**Contract gate: PASS.** The final independent review (round 3 plus two delta checks, against the hashes in the session notes) reports that Packet 2A meets its acceptance criteria:

- zero-hold references do not drift;
- there is no unbracketed or root-finding solver;
- no empty set is accepted;
- emitted (q, v, a) are consistent in every mode;
- every disposition is labelled with a reason;
- an unholdable initial state produces an explicit rejection;
- sweeps stay within the declared tolerances.

**Carried into Packet 2B, which must close them before the baseline is frozen:**

- the loaded-outage fault-containment regression above;
- repeated-trip lockout;
- the no-yaw-authority fallback (M8c).
