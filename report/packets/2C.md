## 3. Evidence provenance (new in 2C)

- `exp/evidence.py` `RunBook`:
  - describes each run with an `exp.manifest` manifest *before* it runs;
  - requires every imported project module to be in the declared source set;
  - scores the run with `sim.metrics.evaluate` (4A.3);
  - records the run specification and metrics under its run_id.
- Tables cite a run_id, or a run-set id that is the hash of the sorted run_ids, which are listed per sample in `task2_results.json`.
- Both scripts publish through `staged_publish`. Outputs appear only after the whole evaluation succeeds and a source-change check passes. The first 2C run exercised this: the check correctly counted the concurrently edited 4A files as a change.
- The robustness readings for saturation rows A and D, and the quantization jitter attribution, are now computed from the numbers. Two prose readings written before the run had gone stale:
  - reading D described a watchdog trip, but the frozen run has none;
  - reading A described a braking clip, but the row shows 0% at the limit.
