## 2. What is measured (definitions: `sim.metrics.METRIC_DEFS`, version 4A.1)

| Measure | Definition | Why it is separate |
|---|---|---|
| `orig` error | q(t) − q_req(t), on the wall clock | Shows the timing given up by reshaping. |
| `gov` error | q(t) − governed reference `c_q_c` | This is what the loop was asked to track. It can be ≈0 while the controller rejects the request or idles. |
| `path` error | q(t) − q_req(σ(t)), where σ = host-tick time − `c_gov_lag` | Error against the original path geometry at the governor's own path time. Forward-filled telemetry is referred to the host tick that produced it. For an ungoverned controller σ = t. |
| `geo` error | Distance of q from [min, max] of q_req over σ ± 0.25 s | A timing-tolerant geometric lower bound. |
| `progress` | Path-clock increments 0 ≤ dσ ≤ host period, with σ clipped to the request duration. Counted only while drive and host are both normal. | Forward clock jumps (replan or realign) are counted separately and never as progress. |
| `completion` | The plant visits every waypoint in order within 2°. It then stays within 2° of the final target with \|q̇\| ≤ 0.1 rad/s for 0.2 s, with the drive normal, the host not in fallback and the request not rejected. Excursion beyond the path range must be ≤ 5°. | Depends only on the plant state and health flags, not on controller-reported path time. Reports `t_complete` against `t_request`. |
| `tracked` | progress ≥ 95 %, path RMS ≤ 2°, no rejected time, and (for finite motions) completed | Reasons for failure are listed in `not_tracked_because`. |
| Strata | Priority: startup > rejected > fallback > recovery > reshaping > normal. Reshaping = governor status reshaped/joining/restricted/over_budget. Fallback = drive mode 1 or host fallback. Recovery = 0.5 s after a fallback/rejected span ends or after a `rearm_after_*` event. | Each stratum reports time share, duration, and orig/gov/path/geo RMS and peak. The shares sum to 100 %. |
| Current | Host demand before its own clamp, (τ_ff + τ_fb)/K_T (**Calculated** from telemetry); drive target `i_raw`; applied `i_tgt`; measured `i` | Also: active-limit range and change times; target and measured excess over the limit, and how long the measured excess lasts; saturation time, entries and longest episode; host saturation; voltage-limit share and entries; final winding temperature. |
| Faults | Sorted events, counts, and latch → re-arm pairs with downtime | Also the count, total, longest and list of spans for drive fallback, host fallback and rejection. |
| Yaw | Requested vs delivered half peak-to-peak amplitude (after 1 s, and over the final 1 s) and zero-crossing frequency | Also scale requests (t, scale), final and minimum scale, whether a planner was available, and time flagged incompatible. |

All thresholds are **project design assumptions**, not assessment requirements (plan §2 rule 7). They are declared as constants in `sim/metrics.py`.

**Manifest** (`exp.manifest.make_manifest`):

- **Result-determining fields:** sha256 of every project module imported under `ctrl/`, `sim/` and `exp/`, and a combined code hash. The full nested `SimConfig` (it round-trips to an equal dataclass). A description of the roll and yaw request objects, the seed, time window and yaw-coordination flag. The controller class, name, scalar options and components. The supervisor's attributes. Waypoints and `t_request`. The metrics version and definitions.
- **`run_id`:** sha256 of the result-determining fields.
- **Recorded beside them:** git commit, dirty flag and dirty sources (read-only `git --no-optional-locks`), and the Python/NumPy/SciPy versions and platform.

**`staged_publish(target, check=)`:** outputs go to a `.stage-*` directory. Files are copied next to their destinations and renamed over them only after the evaluation body and `check()` both succeed. On any failure the target is untouched and the stage is kept with a `FAILED` traceback. The demo's `check` refuses to publish if any hashed source changed during the evaluation, or if the runs do not share one code hash.

`tests/test_metrics.py` covers:

- **Standing still gets no credit.** Four standing-still cases, all scored not tracked and not completed:
  - a synthetic rejected/stationary log (governed error 0, path error at the frozen σ ≈ 0);
  - a stationary log whose telemetry *claims* accepted, zero-lag tracking (governed error 0, progress 100 %);
  - an ungoverned stationary log;
  - both diagnostic controllers in real closed-loop runs.

  A perfect-tracker positive control passes, so these checks are not vacuous. Completion is refused if a waypoint is skipped, or if the drive is in fallback during the final settle.
- **Path clock and progress.** σ is reconstructed exactly with a host divider of 2 (tolerance 1e-12). A forward clock jump is counted as a jump and never as progress.
- **Strata.** A synthetic log with known phases gives 25/12.5/12.5/12.5 % for reshaping, fallback, recovery and rejected, and the shares sum to 100 %. A real run with a 60 ms command outage also sums to 100 %, with non-zero fallback and recovery time and `cmd_timeout` in the timeline.
- **Current, faults and yaw.** Saturation entries and duration, limit-change time, and how long measured current exceeds the limit. Latch → re-arm pairing, including a latch with no re-arm. Yaw amplitude ratio of 0.5 and frequency of 1.5 Hz.
- **Manifest.** Config round trip, including nested tuples. The manifest JSON round-trips. `run_id` is stable for an identical spec and changes with the seed or a controller option. Editing a temp source file changes the code hash, and `changed_sources` names that file.
- **Staged publish.** An exception mid-evaluation leaves the target byte-identical, adds no new files, and keeps a stage with a `FAILED` note. A failing `check` also leaves the target untouched. A successful publish replaces the files and leaves no stage or temporary files.

## 5. Remaining limitations

- **Thresholds are assumptions.** The pass/fail flags depend on the declared constants: 95 % progress, 2° path RMS, 2° / 0.2 s / 0.1 rad/s settle, 5° overshoot, 0.5 s recovery window and ±0.25 s geometric window. Packet 4B/Task 3 must freeze them before evaluation.
- **Path error and progress rely on the path time the controller reports** (`c_gov_lag`). The rate cap (dσ ≤ host period) and the exclusion of jumps stop that clock from over-reporting progress. A controller could still under-report lag and push path error towards wall-clock error, which is conservative. Completion is the only measure that ignores the controller's clock: it uses only the plant state and the health flags.
- **Progress on a periodic request is still a path-clock fraction, not delivered physical speed.** The finite motions M1–M3 are the useful-motion measure. They are assumptions chosen for comparison, not logged trajectories.
- **Strata interact.** With repeated faults the recovery window can dominate (M2: 72 %). The startup span (before the first command reaches the drive) is its own stratum and does not open a recovery window.
- **Winding temperature is only the final value** (`meta['T_winding']`); no per-tick temperature is logged. The host-demand current is reconstructed with nominal K_T, which matches what the baseline host uses.
- **Yaw frequency** comes from the spacing of zero crossings, which assumes a single dominant tone. Amplitude is half the peak-to-peak.
- **Manifest scope.**
  - It hashes the project modules that were imported. It does not hash data files, the interpreter or libraries; their versions are recorded but excluded from `run_id`.
  - `describe()` records object attributes; the code behind them is covered by the file hashes.
  - In a `git archive` export the git fields are `None`.
- **`staged_publish` limits.** Destinations are replaced file by file, after every copy has succeeded. The final rename loop is therefore not a multi-file transaction. Stale files already in the target are not deleted.
- **Adoption.** Nothing here is wired into `task2_eval.py`, following the file-ownership rule. Existing Task 2 tables have no manifests or run_ids yet.
- **Review.** No independent review of this packet has been performed.

## 6. Proposed interface changes for the controller owner (Proposed)

Not implemented here; these files belong to the Packet 2B owner.

1. **Emit `gov_sigma` explicitly, NaN while uninitialised.** Today `gov_lag` is 0.0 before the first valid feedback and after `replan()`, which is indistinguishable from zero lag; 4A treats "host idle with lag exactly 0" as unknown. Also emit a `gov_mode` index (PATH/JOIN/STOP/HOLD) and a replan counter, so path-clock jumps can be attributed.
2. **Log per-tick drive-supervisor state:**
   - winding temperature `T`;
   - the new `fault` / `fault_id` / `locked` fields from `Drive.tick` in the 2B work in progress;
   - the active limit's source (schedule or thermal).

   This would make thermal activity and lockouts reportable over time.
3. **Put the controller's disposition log in `log.meta`**: `BaselineController.notices` as (t, status, reason). This lets the fault timeline show reasons such as the no-coordination rejection, not just status indices.
4. **Log the host's unsaturated demand `i_unsat` directly**, instead of relying on (τ_ff + τ_fb)/K_T.
5. **Log planned yaw beside actual yaw.** With the 2B `yaw_plan`/`FollowingYaw` split, log `qy_plan` next to the actual `qy`, so requested, planned (scaled) and actual yaw can be separated. Tag each `scale_log` entry with its source (governor over-budget or saturation monitor).
6. **Add the M2 reproducer** (`exp.motions.m2`, seed 1: 27 trips and 26 re-arms, never completes) to the 2B recovery-by-fault-class regression set.
7. **Packet 4B/2C:** have evaluation scripts call `sim.metrics.evaluate` and `exp.manifest.make_manifest`, write through `staged_publish`, and cite `run_id` in each table row.
