## Confirmed defect

The old completion scorer searches for ordered waypoint visits from the beginning of the entire run. L4 passes only the five test target positions, without telling the scorer when those targets belong to the request. In every one of the 50 baseline, adaptive and oracle-FF held-out records checked, the first +30° test waypoint is credited during calibration, before test entry.

The actual sequence metadata establishes these test segments in requested path time:

| Segment | Start | Move duration | Target |
|---|---:|---:|---:|
| Test 1 | 9 s | 1 s | +30° |
| Test 2 | 11 s | 1 s | −30° |
| Test 3 | 13 s | 1 s | +65° |
| Test 4 | 15 s | 1 s | −65° |
| Test 5 | 17 s | 1 s | 0° |

Each move has a 1 s dwell. The last move ends at path time 18 s (the existing `t_request` completion reference); the final dwell ends at 19 s; the log runs for 22 s including slack. Preserve these distinct quantities. A delayed governor may reach these segments later in wall time. Merely discarding the first nine wall-clock seconds is therefore insufficient. Legitimate final settling may occur during the existing slack.

## Required scoring contract

1. Test waypoint credit belongs to the intended test segment, expressed in governed path time. Neither calibration nor an unrelated crossing during another segment may earn that credit.
2. A missing or reordered target cannot disappear behind a final-position completion flag. Record per-target visits, their actual elapsed and path times, and missing targets.
3. Completion time remains elapsed time from run start, including calibration, reshaping and delays. Do not subtract calibration to make the experiment look faster.
4. The final target still requires the existing healthy settling and post-arrival hold/fault conditions; test-phase scoring cannot erase whole-run safety evidence.
5. Existing Task 2/4B callers without a phase protocol retain their current scoring behavior. The new protocol and version must survive manifest serialization/rebuilding.
6. Any semantic strengthening beyond removal of calibration credit must be disclosed as a retrospective scoring correction. The original experiment and registration remain preserved.

## Implementation

- `sim/metrics.py` (metrics version 4A.3 → **4A.4**): `completion(..., waypoint_windows=)` scores each target only inside its own `[start, end)` window of governor path time. The final window is unbounded so settling may use the slack. Visits are ordered, and each target's elapsed time, path time and missing status are recorded. Completion time is elapsed from run start, so calibration and delays still count. Whole-run overshoot and the existing final settle / post-arrival fault rules are kept. Invalid protocols (count mismatch, unordered, overlapping, non-finite, or a bounded final window) raise `ValueError`.
- Without `waypoint_windows`, the old code path is unchanged, so Task 2 and 4B callers are unaffected.
- `exp/motions.py`, `exp/manifest.py`, `exp/evidence.py`: an optional `waypoint_windows` field is carried through manifests (it enters run_id when present) and through `rebuild_run`.
- `exp/task3_l4.py`: the windows come from the actual sequence metadata (test segment starts in path time). Rows record `waypoint_visits` and `missing_waypoints`. An `--out` option allows staged replays.

## Limitations

- **Crossing, not settling:** intermediate targets are still scored as crossings within tolerance inside their segment; only the final target has a settle rule. This is unchanged from the old semantics except for the window.
- **Overshoot scope:** overshoot is whole-run, including calibration, as the contract requires.
- **Old records:** the published files in `report/task3_ceiling_*` remain the old-scorer version until R4 republishes. They are equal in completion counts, but their run_ids and metrics version differ.
