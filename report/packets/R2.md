# R2 — Task 5 windows, units and prediction inference

**Status:** implemented and verified; independent review pending. Corrected output is staged in [`report/staged/R2/`](../staged/R2/). Publication is R4. `report/task5_registration.json` is unchanged; this was checked byte-for-byte against the committed file. This is a **retrospective correction** of the original analysis: the same frozen controller (fingerprint `7d857df507c389c9`), the 12 original conditions and seeds 21–23 are replayed. It is not a new prospective experiment.

## Reproduced defects

1. **Mixed windows.** `_row()` restricted current to [2, 8) s but copied governed and original RMS, clipping and path speed from `summarize()`, which covers 0–8 s.
   - Regression: a synthetic log with large startup error and a small in-window error. The old code reports 5.0° governed RMS where the window value is 0.1°.
2. **Unit error.** `predicted_coupling_peak_current_A` copied `c_tau_cpl`, which is the controller's coupling feed-forward *torque* in N·m.
   - Regression: the old field name must be absent, the torque must be reported in N·m, and the current must be that torque divided by nominal Kt.
3. **Inference.** The registered numbers are component-level ideal arithmetic. The old write-up treated the coupling-torque match as confirmation, and it read the ±0.15 A tolerance, which contains 0 A, as a meaningful test of the +0.1076 A prediction.

Red/green check: `tests/test_task5_prediction.py`, 4 tests. Against the committed pre-R2 tree the result is `FAILED (failures=3)`; against this tree it is `OK`. Full suite: `Ran 220 tests … OK`.

## Changes (`exp/task5_prediction.py`)

- **One window.** Every windowed quantity (current, governed and original RMS and peak, clipping, path speed) uses the registered [2, 8) s. Whole-run safety evidence (events, trips, clipping, peak current, whole-run governed RMS) is kept in a separate `whole_run` field. Definitions are in `METRIC_DEFS` in the output.
- **Units.** `controller_coupling_ff_peak_torque_Nm` (N·m) replaces the mislabelled field, with `controller_coupling_ff_peak_current_A` = torque / nominal Kt (the commanded FF current). `ideal_true_coupling_peak_current_A` = true coupling / true Kt (what an ideal controller would need). The two currents are kept distinct.
- **Measured residual.** `coupling_residual_peak_Nm` is the coupling torque the unchanged FF leaves for feedback, max|τ_couple(t + T_act) − (Kt_true/Kt_nom)·ĉ(t)|, reported for FF on only.
- **Prediction matrix.** Each registered prediction is set against the quantity actually measured, with its unit, window, tolerance basis and verdict (`prediction_matrix` in the JSON; table in the staged `task5.md`).

- The verdict fails at every alignment.

**What changes from the published Task 5:**

- **Windowed governed RMS is higher,** because the quiet yaw ramp in 0–2 s no longer dilutes it. With the weak motor and FF on the median is 0.328° (was 0.289°), against 0.274° nominal (was 0.242°). With FF off it is 3.936° (was 3.768°).
- **Current peaks are unchanged.**
- **The old "+0.047° paired" figure mixed windows;** the corrected value is +0.054° median and not uniform.
- **Registration audit (`registration_audit` in the JSON):** the results now carry the frozen file's registration. The code-regenerated version differs in two ways:
  - the four prediction numbers, at relative 1e-14, because the code accumulates `t += 0.001` while the file equals sampling at k·0.001 s;
  - an extra `secondary_metrics` key.

  So the file was not produced by the committed function exactly. Registration and original results were first committed together (f19fff2), so git gives **no ordering evidence** that registration preceded the run.
