| Check | Result |
|---|---|
| All 10 steps | exit 0 in **7.8 min** (Mac: 11.7–19 min) |
| String/boolean outcomes (tracked, completed, faults, events, gate statuses, verdicts) | **identical** |
| Result values at the declared tolerance (1e-9 relative) | **0 differences** in all six packets (L2 wall-clock fields excluded) |
| Bit-exact floats | 5,412 of 45,717 differ in the last digits; worst relative difference 3.1e-11 (a 4B path RMS). Counted by `tools/compare_evidence.py` over the six result JSONs, with provenance keys and L2 wall-clock fields excluded |
| run_ids | Task 3 L4 (357) and challenges (96): identical. Task 2: 70 of 177 differ; 4B: 30 of 397 differ; **every one is a Monte Carlo run** |
| Figures | not byte-identical (PNG encoding), but pixel-identical apart from faint anti-aliasing in two Phase 0 plots (0.02–0.11% of pixels) |

**Cause** (found, not assumed): NumPy's `Generator.uniform()` rounds differently on the two CPUs. It uses a fused multiply-add on arm64 but not on x86-64: in 100,000 draws, 6,995 differ from plain `a + (b − a)·u` on the Mac, and 0 on luna1.

- **Knock-on effects:** the Monte Carlo plant parameters differ in the last binary digit, and because the configuration is part of the hashed run spec, so do those runs' run_ids. The one-ulp differences propagate through the simulation to at most 3e-11 relative and never change a discrete outcome.
- **Test fix:** the first luna1 attempt (`727c7f9`) failed one test that compared regenerated draws with the published ones bit for bit. It now checks the same draws to 1e-12 relative (`tests/test_task4b.py`).

**Method.** Every comparison in this packet can be rerun with `uv run python tools/compare_evidence.py <reproduced report dir>`. It checks values within 1e-12 + 1e-9·max(|a|, |b|), string/boolean equality, bit-identity counts, run_id sets with Monte Carlo classification, and figure bytes and pixels. (R6 round 2 counted 5,442 of 35,159 with a different leaf set; the worst difference and the tolerance verdict agree.)

**What this establishes.** The published evidence reproduces exactly on the same platform, from a fresh install. Across operating systems and CPU architectures it reproduces to about 1e-11, with identical outcomes. Bit-identity across architectures is not achievable with NumPy's random generators, so a cross-platform check should compare within tolerance and match Monte Carlo runs by (scenario, seed), not by run_id.

## Limitations

- **Two environments, one library set:** macOS arm64 and Linux x86-64 are verified, both with the locked library versions. Other library versions (for example NumPy 1.x) and Windows are untested.
- **Install paths:** the pip path (`pip install -r requirements.txt`) was not separately exercised; it installs the same exact pins as `uv sync`.
- **The PDF is not in the snapshot:** it is ignored by git, and no step reads it.
- **Tests are not validation:** passing tests show that the code does what the tests check; they do not validate the experiment designs.
